## 6. МЕТОДОЛОГИЯ (соблюдать)

**Аудит после каждого изменения, все 3 языка, стандарт 174/174 и 0 проблем.** Проверять: canonical (`https://lexonyx.com/<path>`, пропускать при `robots noindex`), `<html lang>`, отсутствие ``` -фенсов и `<style>`-блоков, баланс `<section>`, баланс `<div>`, баланс `<a>`, UK без русских слов (ы/э/ъ вне комментариев), баланс скобок CSS.

**Технические грабли (проверены на практике):**
- Перед подсчётом баланса **вырезать `<script>` и комментарии**: `re.sub(r'<script.*?</script>','',h,flags=re.DOTALL)`.
- Баланс `<a>` считать через `re.findall(r'<a[ >\n\t]',clean)` — наивный `count('<a ')` даёт **ложные срабатывания** на тегах с переносом строки.
- Скрипты с кавычками/эмодзи **писать в `.py`-файл**, не в inline-heredoc — иначе SyntaxError на f-строках.
- **Точные строки не работают** для операций по шапке/навигации: разметка неоднородна (разные отступы, регистр, на одной EN-странице был затесавшийся русский текст). Использовать **regex по href**, идемпотентно: сначала удалить все вхождения, потом вставить ровно одно.
- **`@import` без скобок** ломает парсер блоков (склеивается со следующим `:root`, теряются токены) — вырезать `@import`-строки перед разбором.

**Связка секций и контента — критично.** Компоненты `schema-line`, `rhythm-body`, `advisory-card`, `role-card-dark`, `jurisdiction-hub-card` имеют **светлый текст на прозрачном фоне** — они рассчитаны только на тёмные секции. Флип `section-dark → section-light` делает их **невидимыми**. Всегда проверять тип компонентов внутри секции перед сменой фона.

**Упаковка ZIP:** ASCII-safe имя (кириллица в именах ломает Windows-распаковщики), исключать `*.py`, `__pycache__`, `*.bak`, `.DS_Store`. **Всегда новое имя файла** (у меня кэшируется старый архив — уже был случай, когда я не видела изменений).
